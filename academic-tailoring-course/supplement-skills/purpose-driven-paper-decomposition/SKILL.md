## I — 方法论骨架（Interpretation）

1. 先把“读这篇论文”改成一个具体任务：筛选、复现、比较、引用归属，还是寻找可改造部件。
2. 按任务分配阅读深度，不把每篇论文都处理成同样完整的摘要。
3. 用摘要定位任务与总体主张，用引言定位问题缺口和作者声明。
4. 用方法章节画出主干、模块、输入输出、数据流和依赖。
5. 用实验与消融检查哪些部件真正被单独比较，哪些只是作者的结构描述。
6. 把四处证据汇合成 A/B/C 组件表，并把代码、附录、引用和版本作为归属核验入口。
7. 对冲突、缺失和无法隔离的效果保留原状，不能用一个漂亮的组件图替代证据。
8. 最终交付的是可追溯的部件—证据地图和待查清单，而不是换一种写法的论文摘要。

## A1 — 书中的应用（Past Application）

### 案例 1：讲者用自己的返修稿定位基准与模块

- **证据状态**：课程自述 / 示例；候选 c05 的引文标为 ASR 待音频复核，不能升级为普遍有效性事实。
- **问题**：讲者需要示范如何从一篇论文中迅速找出任务主体和新增部件，而不是读完后只能复述摘要。
- **使用方法**：以自己的返修稿为例，先从摘要定位“基于什么”的主体，再从引言末段找三层注意力及各层名称，最后用方法目录和框架图交叉核对。
- **结论**：把双向 Transformer 作为基准 A，把三层注意力表示为独立模块，形成可追溯的 A/B/C/D 部件图。
- **结果**：方法目录中找到了对应位置；这是课程演示得到的结构化表示，仍需代码、实验和引用核验，不能视为独立复现结果。

### 案例 2：讲者回到自己的消融表核对模块边界

- **证据状态**：课程自述 / 示例；候选 c07 的引文标为 ASR 待音频复核，且案例明确保留归因不严谨的边界。
- **问题**：仅凭模块名称和框架图，无法判断三个部件是否确实被单独验证。
- **使用方法**：回到自己论文的消融表，把关键帧选择、融合注意力等部件与 A、A+B、A+C、A+B+C 的启用/禁用配置逐项对应。
- **结论**：实验表可以反向帮助确定模块边界，但模块名、结构图和指标变化不能自动构成因果归因。
- **结果**：三个模块都找到对应实验设置，同时讲者承认表格设计和归因“不特别严谨”；因此本例既示范方法，也示范何时应收窄结论。

## A2 — 触发场景（Future Trigger）★

### 用户会在什么情境下需要这个 skill？

1. 用户手上有一批论文、时间有限，但需要围绕某个研究任务决定哪些必读、选读、暂不读，并留下后续补读清单。
2. 用户要比较论文或复现组件，要求从摘要、引言、方法和实验中找出基准、模块、接口、数据流及各自证据，而不是得到一篇普通摘要。
3. 用户发现方法章节、实验表、公开代码或引用归属互相不一致，需要把实现降级为待核验材料，而不是直接放进 A/B/C 组件图。

### 语言信号（用户的话里出现这些就应激活）

- “先帮我筛论文、按任务分层、告诉我哪些先读” / “paper triage”, “purpose-driven reading”
- “把这篇拆成基线和模块、画 A+B+C、找接口和数据流” / “paper decomposition”, “A/B/C”
- “代码和方法对不上、这个模块到底归谁、能不能复现” / “reproducibility”, “provenance”

### 与相邻 skill 的区分（阶段 3/4 定稿）

- 与 u06 · 基准模型可复现闸门 的区别：本 skill 先定位和组织论文证据；u06 再决定某个候选基线是否具备代码、数据、许可、环境和可重复运行条件。
- 与 u05 · 可变粒度的 A+B+C 研究架构 的区别：本 skill 拆解已有论文并标出角色与证据；u05 用这些部件设计研究边界，处理跨论文继承和新增贡献。
- 与 u08 · 组合研究实验闭环 的区别：本 skill 产出组件图和待核验项；u08 在基线可运行后执行公平对比、消融、重复实验和保留/停止判断。

## E — 可执行步骤（Execution）

当 skill 被激活后，agent 应按以下步骤执行：

1. **锁定阅读任务与深度**
   - 记录用户要做的决定、论文/版本范围和时间预算。
   - 完成标准：得到一句明确的阅读目的，并将每篇论文标为必读、选读或暂不读；“暂不读”必须附后续触发条件。
   - 回退条件：用户只要普通摘要、翻译或润色时不启动本流程，改走对应的文本任务。

2. **建立四入口证据表并交叉拆解**
   - 摘要记录任务、问题、方法和总体结果；引言记录缺口与贡献声明；方法记录 A/B/C、接口、数据流和依赖；实验记录对比、消融、限制与归因证据。
   - 用代码、附录和引用核对预处理、数据划分、实现版本与方法归属；每个组件至少标记来源位置、证据状态和冲突项。
   - 完成标准：每个已确认组件都有可回溯的文本位置和至少一项验证证据；单一章节支持、代码冲突或来源不明的内容标为“待核验”。
   - STOP 条件：若只有作者声明、只有一处章节提及，或实验没有隔离 B/C，停止“已确认贡献/因果作用”的判断。
   - 待核验条件：方法与公开代码在预处理、数据划分、参数或版本上不一致时，保留两边记录；差异解释前不得把代码实现当正式基线。

3. **输出组件—证据地图与下一步清单**
   - 输出字段至少包括：阅读任务、论文/版本、A/B/C 角色、四入口定位、接口/数据流、代码与引用核验、证据状态、未确认边界。
   - 完成标准：读者能从表格追溯每个组件为何被纳入、为何被降级或为何不能归因；输出不以摘要替代证据表。
   - 回退条件：若论文没有标准模型结构，将 A/B/C 改写为研究对象、基础方法和变化单元；若连这三类角色也无法稳定识别，则只输出结构化证据表并标记“不适用”，不得强行套用 A/B/C。

## B — 边界（Boundary）★

### 不要在以下情况使用此 skill

- 用户只需要摘要、翻译、格式整理或语言润色，不需要论文部件、证据归属或复现核验。
- 用户已经有可运行且版本固定的基线，问题是跑实验、做消融、比较方差或决定是否保留组合；这属于实验闭环而非阅读拆解。
- 用户询问当前学校培养方案、期刊 scope、投稿规则或就业/政策事实；本课程是经验材料，不能替代实时、正式来源。
- 用户要求把“模块越多”“指标变高”直接写成创新，或要求隐藏来源、预先冻结结论、规避实验与归因检查。

### 课程中对应的反例 / 失败模式

- ce05：把整篇论文当作线性文本，读完只能复述摘要，无法指出基准、模块、实验和结论之间的关系。
- ce07：只堆叠多个模块，既不说明各项变化解决的问题，也不记录来源、单项对照或贡献边界。
- ce08：没有真实实验、日志或可核查记录就宣称性能提升；本 skill 只能标记证据缺失，不能替它补出结果。
- c07 的示例还显示，即使做过消融，表格设计和归因也可能不够严谨，不能把“有消融”自动当成充分证明。

### 阶段 0 的批判边界与作者盲点

- 这是一套面向中国大陆研究生、理工科/计算机/AI 语境的课程经验地图，不代表文科、医学、实验科学、艺术、海外培养体系或所有学校的规则。
- A/B/C 是分析索引，不是创新、因果、原创性、合法复用或发表/毕业结果的证明；组合是否成立仍取决于问题价值、基线质量、数据、实验预算、许可和制度要求。
- 分层阅读若被永久化，可能漏掉相关工作、引用归属、实验限制和反例；正式综述、比较和投稿审计必须补读相应材料。
- 视频转写含 ASR 待复核边界，文档材料还可能有 OCR、字体映射或模板示例；专名、数字、规则和个人经验不能脱离来源升级为普遍事实。
- 对没有标准模型结构的质性、流程型或跨领域论文，A/B/C 需要显式映射；映射失败时应回退，而不是强行套模。

### 容易混淆的方法论

- u05 · 可变粒度的 A+B+C 研究架构：关注研究设计中 A 的粒度如何变化、旧贡献如何冻结，本 skill 只负责把论文读成可追溯部件。
- u06 · 基准模型可复现闸门：关注候选基线能否被公平、合规地复现，本 skill 不替代实际运行和环境审计。
- u08 · 组合研究实验闭环：关注一次接入一个模块后的对比、消融、方差、成本和停止，本 skill 不把阅读证据冒充实验结果。
- u11 · 问题—模块—证据叙事映射：关注证据冻结后如何写主张和章节，本 skill 不在结果稳定前生成论文故事。
