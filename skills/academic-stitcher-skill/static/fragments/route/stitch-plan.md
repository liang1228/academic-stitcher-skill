# Route: stitch-plan

Use for research ideas, baseline/module selection, thesis topics, opening reports, advisor plans, and experiment roadmaps.

Do not use for polishing supplied prose, drafting a named section, auditing a manuscript, or maintaining a skill package.

## Procedure

1. State the target and decision checkpoint.
2. Inventory supplied evidence and missing constraints.
3. Identify the inherited task/baseline/paper family.
4. Define the exact failure mode; do not invent one after choosing a module.
5. For each candidate delta, record source, license, interface, actual change, mechanism, prediction, and required evidence.
6. Reject deltas without attribution, compatibility, feasibility, or a fair test.
7. Convert surviving deltas into minimum work packages with stop/go criteria.

## Contract

Use the `stitch-plan` headings from `static/core/output-format.md` exactly. Under `Quality Gates`, include compliance and fair-comparison findings. Under `Missing Inputs`, list only inputs that change the decision.

If the user supplies no comparable papers or baseline evidence, produce a scoping matrix and retrieval plan rather than claiming a novel direction.
